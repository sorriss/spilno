# Spilno — архитектура страниц и данных

## Карта маршрутов
Всё в `src/app/app.routes.ts`. Экран без реализации подключён через `stub()` и показывает заглушку; когда экран готов, заменяем `stub()` на его `loadComponent`.

| Маршрут | Экран | Защита | Статус |
|---|---|---|---|
| `/welcome` | Онбординг | guest | **готов** |
| `/sign-in` | Вхід | guest | **готов** |
| `/privacy` | Умови та конфіденційність | все | **готов** |
| `/family-setup` | Створити / приєднатися | auth | **готов** |
| `/new` | Нова витрата (без таб-бара) | auth, family | **готов** |
| `/tabs/overview` | Огляд | auth, family | **готов** |
| `/tabs/transactions` | Операції | auth, family | **готов**, без поиска и фильтров по категории |
| `/tabs/transactions/:id` | Деталі операції | auth, family | **готов**: просмотр и удаление, правки пока нет |
| `/tabs/transactions/:id/split` | Редагувати поділ | auth, family | заглушка |
| `/tabs/settle` | Розрахунки | auth, family | **готов**, без «Нагадати» |
| `/tabs/settle/history` | Історія | auth, family | **готов** |
| `/tabs/more` | Ще | auth, family | **готов**, без монобанка и настроек устройства |

Этап 2 (`/review`, `/analytics`, `/tabs/more/mono/*`) добавим вместе с экранами.

Переходы при запуске: нет сессии → `/welcome`; есть сессия, но нет семьи → `/family-setup`; иначе → `/tabs/overview`. Экраны внутри таба лежат вложенными маршрутами, поэтому каждый таб хранит свой стек и таб-бар остаётся виден.

## Структура кода
```
src/app/
  app.routes.ts     карта маршрутов
  core/             supabase-клиент, guards, деньги (без UI)
  i18n/uk.ts        все строки интерфейса
  shell/            таб-бар, строка операции
  pages/<экран>/    страница + её *.data.ts (запросы и сборка данных экрана)
src/styles.scss     дизайн-токены (--sp-*, --ion-*)
supabase/migrations схема, RLS, RPC
supabase/tests      проверка схемы на PGlite
```
Страница не обращается к Supabase напрямую, это делает её `*.data.ts`. Общий компонент выносим из страницы, когда он нужен на втором экране.

## Схема БД
Источник правды — `supabase/migrations/`.

```
families ─┬─ family_members ─┬─ accounts
          │                  ├─ transactions ── transaction_shares
          │                  └─ settlements
          ├─ family_invites
          └─ categories
```

| Таблица | Что хранит | Кто видит | Кто пишет |
|---|---|---|---|
| `families` | название, базовая валюта | участники | owner; создание через `create_family` |
| `family_members` | имя, роль, цвет, `left_at` | участники | owner |
| `family_invites` | одноразовый код, срок 7 дней | owner | `create_invite`, `join_family` |
| `accounts` | счета участника | владелец счёта; семья при `is_visible_to_family` | владелец счёта (не viewer) |
| `categories` | категории семьи | участники | owner, member |
| `transactions` | операции | общие и внутренние переводы: все; личные: только автор | автор (не viewer), общие также owner |
| `transaction_shares` | доли общей операции | как у операции | как у операции |
| `settlements` | «Отримав» / «Пробачити» | участники | только получатель |
| `member_balances` (view) | баланс участника | участники | — |

Что гарантирует сама БД:
- сумма долей равна сумме общей операции (отложенный триггер, проверка в конце транзакции);
- знак суммы соответствует типу операции;
- ссылки на участника, счёт и категорию только внутри своей семьи (составные FK);
- личная операция записана только на её автора;
- автора и семью операции нельзя изменить, а роль может менять только owner.

Отложенный триггер означает, что операцию с долями нельзя записать двумя отдельными запросами PostgREST, поэтому экран «Нова витрата» пишет их через RPC `add_transaction`. Он работает с правами вызывающего, так что RLS действует как при прямой записи.
