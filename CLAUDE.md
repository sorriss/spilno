# Spilno

Семейное приложение для учёта и деления общих расходов: кто сколько потратил, как делим, кто кому должен. Сильная сторона — семейный шеринг (у Wallet/BudgetBakers его нет). Название от «спільно» — вместе.

## Документы — читать перед работой
- `docs/decisions.md` — принятые решения: стек, Supabase, монобанк, модель данных, оценка объёма.
- `docs/design.md` — карта приложения, экраны, стиль, нерешённые допущения, порядок разработки.
- `docs/architecture.md` — маршруты, структура кода, схема БД и кто что видит.
- Дизайн: Figma https://www.figma.com/design/Pk5klZ9grzKxjf8ci5wqjl (страницы: Карта, Основні екрани, Перший запуск, Монобанк, Стиль). Слои плоские — это референс, а не источник компонентов.

Новые решения записываем в `docs/decisions.md` (кратко: что решили и почему), а не только в код.

## Стек
- Клиент: Ionic + Angular + Capacitor, TypeScript. Один код для iOS, Android и веба/PWA.
- Бэкенд: Supabase — Postgres, Auth, Realtime, RLS, Edge Functions (TypeScript).
- Банк: Монобанк Personal API (этап 2). Каждый участник подключает свой токен.

## Правила, которые нельзя нарушать
- **Деньги — только целые копейки** (`bigint` в БД, `number`-целые на клиенте, без float). Знак как у mono: расход < 0, доход > 0. Округление при делении — остаток копеек раздаём по одной первым участникам, сумма долей всегда равна сумме операции.
- **Приватность через RLS.** Каждая таблица с данными семьи — под политиками RLS; участник видит только свою семью, личные операции видит только автор.
- **Токены монобанка — только на сервере.** Таблица без RLS-политик для клиента (позже Supabase Vault). На клиент токен не возвращается никогда. Запросы к mono — из Edge Functions.
- **Внутрисемейные переводы не считаются расходом** и не должны задваиваться (флаг «внутренний перевод»).
- Лимиты mono Personal API: выписка ≤ ~31 дня за запрос, ~1 запрос в минуту — импорт истории идёт очередью.

## Интерфейс
- Язык интерфейса — украинский. Все строки — через i18n, не хардкодом в шаблонах.
- Формат сумм: `1 248,60 ₴` — неразрывный пробел между тысячами, запятая, знак валюты после; «−» (U+2212) для расходов, «+» для дохода, перевод без знака и серым. Цифры табличные (`font-variant-numeric: tabular-nums`).
- Стиль «Спільний стіл»: шрифт Manrope; цвета, радиусы и отступы — дизайн-токены из `docs/design.md` (CSS-переменные Ionic), не литералы в компонентах.
- Цвет несёт смысл: синий `#1E44C0` — «вам винні», оранжевый `#A3420D` — «ви винні» и холды. Касательные цели ≥ 44px.
- Навигация: таб-бар Огляд · Операції · ＋ Нова витрата · Розрахунки · Ще.

## Объём
- MVP: семья и роли (owner/member/viewer), приглашение по коду, ручной ввод, деление (порівну / частками / сумами), баланс «кто кому должен», расчёты.
- Этап 2: импорт монобанка, очередь «Розібрати», правила общих трат, аналитика.
- Не цель: банковская синхронизация уровня Wallet.

## Статус
Есть каркас, схема БД, вход по email-коду, экран семьи с приглашениями, «Огляд» и «Нова витрата». Всё это проверено на настоящей базе. Новые миграции применяем вручную в SQL Editor. Остальные экраны — заглушки, карта в `docs/architecture.md`.
Следующий шаг: «Операції», список шагов в `docs/design.md`.

## Команды
- `npm start` — dev-сервер, подключён к Supabase. Для демо-данных без входа поставьте `supabase: null` в `src/environments/environment.ts`.
- `npm run start:lan` — то же, но сервер виден в локальной сети: `http://<IP компьютера>:4200`.
- `npm run build` — прод-сборка.
- `npm test -- --watch=false` — юнит-тесты (Vitest).
- `npm run test:db` — миграции, RLS и инварианты денег на PGlite, без Docker.
